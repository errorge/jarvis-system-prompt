# 07 · 故障排查

## 改了配置没生效

- 配置（options）是**下一条请求**生效，当前已发出的请求不变
- 确认改的是同一个插件实例：`magpie plugin list` 看路径/包名
- 确认 agent 在 `agents` 名单里、且 `settings.<agent>.enabled` 不为 false
- 确认请求工具数 ≥ `minTools`（旁路请求本来就不改）

## 改了代码没生效

- 必须 `magpie plugin add <目录>` 重载；只改文件不重载无效
- 仍无效时完全退出 magpie 再启动（排除进程内缓存）

## 请求完全没被改写

- 该 agent 的请求**没走 magpie**：客户端里自选了直连供应商。把 base URL 指回 magpie
  （默认 `http://127.0.0.1:3425`）或 `magpie <agent> <model>` 写回配置后重启客户端
- `enabled=false` 或 agent 不在名单
- 身份行写法变了：抓包看第一行，更新 `prompt.js` 的 `identities` 正则

## 自定义规范出现多份

- 本插件已做全局幂等（多块/跨阶段/重复 system/重试都只一份）
- 若仍见多份：确认跑的是本包代码（`magpie plugin add` 重载过），并检查是否有**别的**
  插件/客户端自定义指令也在注入同一段文本

## 旁路请求（标题/审查）被改了

- 提高 `minTools`（默认 3；旁路通常 0 工具）
- 若某旁路开始带工具，改用 `settings.<agent>.enabled` 或名单精确控制

## 设置页打不开 / 空白

- `magpie plugin list` 应有 `page Jarvis` 一行；没有则重新 `plugin add`
- 本地目录安装缺 `README.md` 会报"无法读取该文件夹的 README"——补上即可
- 完全退出 magpie 再启动（列表缓存）
- 页面读配置失败会显示只读报错行，重新可见时自动重试；不要在这种状态下强行保存

## 担心弄挂请求

- 插件 fail-open：任何异常原样放行
- 随时 `magpie plugin off jarvis-system-prompt` 一键恢复原提示，不留残留

##  still 有问题

带上这三样去问：`magpie plugin list` 输出、`magpie plugin options …` 输出、
一条出问题请求的系统提示词前 200 字符 + 工具数。
