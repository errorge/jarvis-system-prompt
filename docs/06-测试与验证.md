## 验证真实请求（推荐抓包对比）

如果你的上游是录制/分析类服务（或任何能回看请求体的网关），发一句消息后检查系统提示词：

| 检查点 | 期望 |
|---|---|
| 身份行 | 变成你选的样本 |
| 默认 `IMPORTANT: …` 段 | remove 档下消失 |
| 环境块 / skills / agent types / 日期 | 原样保留 |
| 工具定义 | 数量与内容不变 |
| 自定义规范份数（custom 档） | **恰好 1 份** |
| 标题/审查等旁路请求 | 完全未被改写 |

## A/B 验证法（最严格）

同一句输入、同一分钟，只切换插件开关，对比两条请求：

```bash
magpie plugin off jarvis-system-prompt && <agent> -p "clean-check"
magpie plugin on  jarvis-system-prompt && <agent> -p "clean-check"
```

diff 两条请求的系统提示词：**应当只有身份行和安全段两处差异**，其余逐字相同。
这能排除"环境漂移"（工具/技能/MCP 随时间变化）造成的误判。

## 旁路门禁验证

在 agent 里新开一个会话发一句话（会触发起标题请求），抓包看那条 0 工具的请求：
它的系统提示词应是客户端原文（如 "Generate a concise title…"），不含你的样本或规范。
